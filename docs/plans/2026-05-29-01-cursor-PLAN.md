## Part A — P0: `/ultrathink` → `/oramasys` brand retirement (code)

### A.1 Goals

1. **HTTP:** `POST /ultrathink` becomes **`POST /oramasys`** (canonical). Optional **301/308 or duplicate route** for one release only if external clients still call `/ultrathink`.
2. **Types:** `UltraThinkRequest` / `UltraThinkResponse` → **`OramasysRequest` / `OramasysResponse`** (Pydantic models in `api_server.py`).
3. **Env:** `ULTRATHINK_*` → **`ORAMASYS_*`** with documented deprecation aliases (read old, write new).
4. **PT bridge:** `normalize_ultrathink_endpoint`, `call_ultrathink_bridge`, `build_ultrathink_http_payload`, etc. → **`orama_*` / `oramasys_*`** names aligned with `orama_bridge.py`.
5. **Routing/backend labels:** YAML/tests using `backend: ultrathink` → **`orama`** or **`oramasys`** (pick one string; recommend **`orama`** in `routing.yml` roles, **`oramasys`** for URL path only).
6. **Files:** Rename `bin/mcp_servers/ultrathink_orchestration_server.py`, `bin/shared/ultrathink_core.py`, `references/ultrathink-5-stages.md`, etc.
7. **Docs:** Update API reference, PERPLEXITY_BRIDGE, SYNC_ANALYSIS, skills — historical mentions may say “formerly ultrathink” once.

### A.2 Non-goals (this pass)

- Renaming the **git repo** (`orama-system` stays).
- Renaming **methodology** prose (“5-stage ultrathink process”) in all archived docs — only **code paths, env vars, wire contracts**.
- Changing **port 8001** (still orama API server unless separately decided).

## Part B — P1: Tiered OpenRouter pipelines (after Part A)

### B.1 Why after rename

Pipeline code should target **`POST /oramasys`** and **`OramasysRequest`** so OpenRouter step metadata (`metadata.pipeline_steps`) never uses retired names.

### B.2 Architecture (unchanged intent)

```
orama POST /oramasys  →  plan recipe + task  →  PT POST /v1/pipeline/run
                                              →  OpenRouterClient (one base URL, one API key)
                                              →  step 1: fast model
                                              →  step 2: strong model
```

| Layer | Responsibility |
|-------|----------------|
| **Perpetua-Tools** | `OpenRouterClient`, `TieredPipelineRunner`, `config/pipelines.yml`, `POST /v1/pipeline/run`, job step telemetry |
| **orama-system** | Recipe selection by `task_type`; call PT; attach `metadata.pipeline_steps` to **`OramasysResponse`** |

### B.3 Config sketch (`Perpetua-Tools/config/pipelines.yml`)

```yaml
models:
  fast:   openai/gpt-4o-mini
  strong: anthropic/claude-sonnet-4.6

recipes:
  classify_then_generate:
    - { name: classify, model: fast,   max_tokens: 256 }
    - { name: generate, model: strong, max_tokens: 4000, input_from: classify }

  extract_then_write:
    - { name: extract, model: fast,   response_format: json_object }
    - { name: write,   model: strong, input_from: extract }
```

### B.4 Shared types (`Perpetua-Tools/orchestrator/contracts.py`)

- `PipelineStep`, `PipelineRecipe`, `StepResult` (PT owns; orama imports).
- Lockstep commit both repos when response shape changes.

### B.5 Env (PT holds secrets)

```bash
OPENROUTER_API_KEY=
OPENROUTER_BASE_URL=https://openrouter.ai/api/v1
PIPELINE_FAST_MODEL=openai/gpt-4o-mini
PIPELINE_STRONG_MODEL=anthropic/claude-sonnet-4.6
PIPELINE_TIERED_ENABLED=0   # default off until validated
```

### B.7 Policy guards

- **Local-first** unchanged: GPU coding on Win/Mac LM Studio; OpenRouter for **orchestration reasoning** only.
- **Privacy:** no cloud pipeline for secrets-heavy payloads; respect control-plane redaction.
- **No second client in orama** — `OPENROUTER_API_KEY` lives in PT only.

### B.8 Pattern reference (OpenRouter)

**Pattern 1 — Classify, then generate**

```python
# Step 1: fast/cheap
classify = client.chat.completions.create(
    model="openai/gpt-4o-mini",
    messages=[{"role": "user", "content": f"Classify: {query}"}],
)
# Step 2: strong
result = client.chat.completions.create(
    model="anthropic/claude-sonnet-4.6",
    messages=[{"role": "user", "content": f"{classify.choices[0].message.content}: {query}"}],
)
```

**Pattern 2 — Extract, then write**

```python
extracted = client.chat.completions.create(
    model="openai/gpt-4o-mini",
    response_format={"type": "json_object"},
    messages=[{"role": "user", "content": f"Extract fields as JSON: {doc}"}],
)
draft = client.chat.completions.create(
    model="anthropic/claude-sonnet-4.6",
    messages=[{"role": "user", "content": f"Write a report from: {extracted.choices[0].message.content}"}],
)
```

Only the **`model`** parameter changes between steps; same endpoint and Bearer token.

### B.9 Success criteria

1. Two OpenRouter calls per request, two models, one API key.
2. `OramasysResponse.metadata.pipeline_steps` lists per-step tokens/latency (no raw prompts in portal).
3. Unit tests offline; optional one live smoke with key.
4. Config-only model swaps (no code edit for model ID changes).
