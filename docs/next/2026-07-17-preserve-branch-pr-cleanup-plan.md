## What these PRs are (and why the bar for deletion is "preserved elsewhere")

They were auto-generated by a workflow to stop stale branches from being
garbage-collected — i.e. explicit "don't lose this yet" markers. So the
deletion test is not "is it old" but **"is this branch's unique content
already preserved in `main` (merged or independently superseded)?"** Only
then is deleting it lossless. This mirrors the PT cleanup already done this
cycle (14 branches, verified-before-delete), where 4 distinct fixes were
confirmed present in `main` before the stale branches were removed.

Key mechanical facts established this cycle (reuse, don't rediscover):
- **Deleting a branch auto-closes its PR** (closed, not merged). This is the
  whole close mechanism — no PR comment/close API calls needed (those 403
  under the current token anyway).
- `git merge-base --is-ancestor` and `git log`/`git diff` are free (local).
- "Cursor: Scan for vulnerabilities = neutral" is a billing stub, not a code
  signal — ignore it.

## The decision tree (one pass, four terminal buckets)

For each branch `B` vs `origin/main`:

- **A — Fully merged.** `git merge-base --is-ancestor B origin/main` → true.
  Content is verbatim in `main`. **Delete, no judgment needed.**
- **B — Superseded.** Has unique commits, but every file it touches already
  carries the equivalent change in `main` (same fix, landed independently).
  **Delete after a Claude spot-check** of the specific behavior.
- **C — Unique.** Has unique commits with novel content not in `main`.
  **Preserve** — open one real, non-draft, mergeable PR (or push to `main`
  if trivial+verified). Never leave as a draft: draft PRs were silently
  closed-unmerged twice this cycle (#251/#252, #186). Do **not** delete.
- **D — Too large / ambiguous.** Unique commit count so high that
  file-level supersession can't be judged cheaply (the `fix6-ci` case).
  **Flag for human**, touch nothing.

## Division of labor — Codex does volume, Claude does judgment

### Phase 1 — Codex: one local manifest (zero API, zero Claude tokens)

1. Single clone of `orama-system`; one batched ref fetch of all 27 heads:
   `git fetch origin $(printf 'pull/%d/head:pr/%d ' for each N)` — one
   command, not 27 fetches.
2. For each branch, compute locally and emit **one compact row** (no diffs):
   `PR | branch | is_ancestor(A?) | n_unique_commits | files_touched |
   unique_commit_subjects`.
3. Bucket A automatically (is_ancestor == true). For non-A, add a cheap
   supersession hint per touched file: does `main` already contain the
   branch's key added symbol/line? (`git grep` of a signature string from
   each unique commit — the same method used to clear the PT cursor
   branches). Mark provisional B vs C vs D.
4. Output: a single markdown table (the manifest) + a `delete-A.sh` script
   listing the confirmed-A branch deletions. **Nothing is deleted yet.**

This is the token-frugal core: 27 branches summarized to ~27 short rows
Claude reads once, instead of Claude pulling 27 diffs.

### Phase 2 — Claude: judgment only where it changes the outcome

1. Read the manifest once. Approve Bucket A deletions wholesale (mechanical,
   already proven by ancestry).
2. For each provisional **B**, spot-check the one signature Codex flagged —
   confirm the behavior really is in `main` — then approve deletion. Batch
   these confirmations; don't re-derive Codex's work, just verify the claim.
3. For each **C**, decide: is the unique content worth keeping? If yes, open
   one real PR per logical unit (non-draft); if it's actually stale/abandoned
   despite being unique, downgrade to delete with a one-line rationale.
4. Leave every **D** untouched; list them for the human with the reason.

### Phase 3 — Execute (batched, verified)

1. Run `delete-A.sh` (Bucket A) — one loop of `DELETE /git/refs/heads/…`,
   each returning 204, auto-closing its PR.
2. Delete approved-B branches the same way.
3. Open C-preservation PRs (if any), non-draft, and merge or hand off.
4. Re-list open PRs once to confirm only intended items remain.

## Token/tool budget (the "efficient" part, made concrete)

- **API calls:** 1 to list the 27 PRs (already done for this plan) + 1
  batched ref fetch + N deletions (1 each, unavoidable, cheap). No per-PR
  GET, no diff-over-API, no comment/close calls.
- **Claude tokens:** one manifest read + a handful of B spot-checks + any C
  decisions. Not 27 diff reads.
- **Codex tokens:** the volume pass, but all local git — cheap, parallel-safe.
- **Hard rule:** if a branch would need more than a couple of signature
  checks to classify, it's **D** (flag), not a token sink. Bounded by design.

---

## Guardrails (carry the session's hard-won lessons)

1. **Verify before delete.** A branch is deleted only after A (ancestry) or
   B (confirmed supersession). Never on name/age alone.
2. **Preserve intent.** These PRs exist to prevent loss; treat Bucket C as
   real work until proven otherwise.
3. **No draft PRs for preservation.** If C content is opened as a PR, it's
   non-draft and actually merged/handed off — the draft trap already cost
   three silent closed-unmerged PRs this cycle.
4. **Deletion auto-closes the PR** — don't attempt (and don't need) the
   comment/close API path.
5. **`fix6-ci`-class branches are D by default** — flagged, not force-judged.
